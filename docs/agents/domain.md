# Domain docs

## Layout and reading rules

This repo uses a single-context layout:
- GLOSSARY.md at the repo root for shared domain terminology.
- docs/adr/ for architecture decision records.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. Domain modeling creates
them when terms or decisions are resolved.

Use the glossary’s vocabulary in issues, code, and tests.
Note missing concepts for domain modeling.
Explicitly flag proposals that conflict with an existing ADR.
